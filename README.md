# FLO — Personal Finance

Персональний фінансовий застосунок українською. React 19, TypeScript, Vite, Tailwind CSS 4, компоненти shadcn/ui на Radix, Recharts, Lucide React, Framer Motion. Валюта звітності — PLN.

## Запуск локально

Потрібен Node.js 22.12+ (або 24) та npm.

```bash
cd flo
npm ci
npm run dev
```

Відкрийте **http://localhost:5173**. Якщо порт зайнятий, Vite покаже інший порт. Для iPhone у тій самій локальній мережі відкрийте Network URL, який надрукує Vite (доступ залежить від мережі та firewall). Сховища iPhone і MacBook окремі.

```bash
npm test          # 14 тестів фінансової логіки та сховища
npm run build    # перевірка TypeScript і production-збірка в dist/
npm run preview  # перегляд production-збірки
```

Браузерні сценарії: `npm run test:e2e` після запуску сервера. У середовищі використано системний Chromium `/usr/bin/chromium`. На MacBook задайте `PLAYWRIGHT_CHROMIUM_PATH` або виконайте `npx playwright install chromium` — конфігурація використає Chromium Playwright, якщо системного немає.

## Можливості

- Додавання, редагування, видалення з підтвердженням; валідація суми, дати та конвертації.
- PLN та USD: оригінальна сума, валюта, ручний курс і фактична PLN-сума зберігаються в операції.
- Дашборд за місяць, інтерактивний розподіл доходів, доходи/витрати за рік, річна статистика та історія місяців.
- Пошук і фільтри операцій; JSON-копії з перевіркою та підтвердженням заміни; CSV усіх операцій, сумісний з Excel/Numbers.
- Порожні місяці без вигаданих записів; від’ємні результати; адаптивна навігація й мобільні форми.

## Дані та точність

`src/lib/finance.ts` містить типи, обчислення, валідацію імпорту та початкові операції. Усі грошові суми зберігаються цілими копійками, округлення конвертації виконується один раз до найближчої копійки. `amountPln` є джерелом фінансових звітів; зовнішні валютні курси не змінюють історію.

Жовтень 2026: 120 USD → 459 PLN (курс 3,825), дохід Vinted 65 PLN, закупівля 200 PLN, перенесена закупівля 70 PLN. Разом: **524 PLN доходу, 270 PLN витрат, +254 PLN результату**. Дати в межах жовтня обрано для стартових записів, оскільки точні дні не були задані; їх можна редагувати.

`src/lib/storage.ts` реалізує інтерфейс `TransactionRepository` через localStorage (`flo.finance.v1`). Початкові дані записуються лише за відсутності ключа. Збережений порожній список залишається порожнім. Пошкоджене сховище не перезаписується стартовими даними. Якщо запис недоступний, зміна відхиляється з повідомленням.

Перенесені 70 PLN — один запис жовтня з `carriedOver: true` та унікальним `transferKey`. Вересневої копії немає. Розрахунки враховують лише дату запису; імпорт відхиляє повторні ID та джерела перенесення. Якщо переносите інші витрати вручну, не створюйте другий запис тієї самої закупівлі.

localStorage доступний лише для конкретного браузера, пристрою та origin (домен + порт). Очищення даних браузера може видалити записи. Використовуйте «Мої дані → Експортувати JSON» для копій і перенесення. Імпорт **замінює** список після підтвердження, не об’єднує його. CSV призначений для таблиць, відновлення виконується через JSON.

## Майбутня синхронізація через Supabase

Сховище винесено за інтерфейс `TransactionRepository`, а компоненти працюють з типізованими операціями. Для підключення Supabase потрібно:

1. Додати авторизацію і таблицю `transactions` із `user_id`, грошовими полями `bigint`, історичним курсом, датою та позначкою перенесення.
2. Увімкнути RLS, доступ лише власника, унікальність `(user_id, id)` і перенесень `(user_id, transfer_key)`.
3. Реалізувати асинхронний адаптер, керування завантаженням, помилками та конфліктами; замінити локальний виклик в App.
4. Перенести JSON-копію після входу, підключити Realtime за потреби.

Supabase зараз не підключений. У браузері ніколи не розміщуйте service-role key.

## Публікація на Vercel

1. Завантажте папку `flo` в GitHub-репозиторій (без `node_modules` і `dist`).
2. Vercel → **Add New → Project** → імпортуйте репозиторій.
3. Якщо `flo` — підпапка репозиторію, задайте **Root Directory: flo**.
4. **Framework: Vite**, **Build Command: npm run build**, **Output Directory: dist**, **Install Command: npm ci**.
5. Натисніть Deploy. Змінні середовища для цієї версії не потрібні.

Після публікації сховище нового домену буде окремим. Експортуйте JSON з локальної версії та імпортуйте його на опублікованому сайті. Публікація сама по собі не додає синхронізацію пристроїв.

## Публікація на GitHub Pages

У проєкті є `.github/workflows/deploy.yml`: push у `main` запускає тести, збірку та публікацію `dist`. Файли папки `flo` мають лежати в корені репозиторію. У GitHub відкрийте **Settings → Pages → Source → GitHub Actions**. Vite використовує відносні шляхи, тому підтримує адреси на кшталт `https://username.github.io/flo/` і окремий домен. GitHub Actions покаже фактичну адресу після успішної публікації. Переконайтеся, що GitHub Pages доступний для типу й видимості вашого репозиторію.
